# 投资研究开发工作流

版本1.0，2026-11-15。用于在现有研究体系上新增公司案例、更新判断和开发工具。原有[SKILL.md](../SKILL.md)保留；本流程不代替投资方法，也不将机械校验等同于研究正确。

## 1. 文件归属与成果

| 文件 | 作用 | 更新方式 |
| --- | --- | --- |
| `SKILL.md`、投资与产业体系 | 原有方法和文章依据 | 用户要求扩充方法时追加，不随案例自动改写 |
| `references/sources/books/` | 文章主源 | 保留原文件，不擅自删除或重排 |
| `scripts/article_library.py` | 提取、检索、审核文章索引 | 索引相关变更才运行其审计或重建 |
| `references/research/companies/<代码-英文名>/` | 有日期的研究报告与模型 | 新日期新增；同日追加版本需明确命名方案，CLI不覆盖 |
| `scripts/research.py` | 新建、发现、复算与校验 | 标准库实现，修改后运行行为测试 |
| `tests/` | 研究工具的回归与错误注入测试 | 验证实际错误能被拦截，避免只匹配文案 |
| `.agents/skills/baozhuo-contribute/SKILL.md` | Codex单线程执行流程 | 保持简短，引用本文件 |

默认最终成果是成对的 `YYYY-MM-DD.md` 与 `YYYY-MM-DD-model.json`。同日第二版起用`--revision 2`等显式编号，生成`YYYY-MM-DD-r2.md`与对应模型，截止日不虚构为次日。研究深度随问题调整，不要求机械填满全部框架；不完整项写明未知和获取办法。

## 2. 每次工作的执行顺序

### 定向与边界

1. 先读 `AGENTS.md`、对应仓库技能及相关旧案例，查看 `git status --short`，保留用户已有改动。
2. 明确对象、证券代码、研究截止日、财务期间、价格日期、问题和成功标准。历史研究只使用截止日前可获得的信息。
3. 用 `python3 scripts/research.py list` 定位已有模型；先对相关案例运行检查，区分原有问题和本次引入的问题。
4. 纯框架解释可直接回答；公司研究接入既有产业与决策模板；工具开发围绕可复现缺陷或明确能力进行最小修改。

### 数据与证据

1. 优先核对交易所、公司公告、财报及客户实际投资；行情核对指定交易日。当前事实联网检索，不能从旧文章或旧模型自动推为最新。
2. 保留原始单位、期间、发布日期、采集日期和链接；关键PDF表格渲染检查。可选文件快照记录仓库内相对路径与SHA-256，避免把临时文件路径当长期证据。
3. 每条模型输入关联来源。观点与假设分列；缺失值不填零。存在冲突时留下冲突与取舍，不能静默选取有利数字。
4. 公司、子公司、客户和产业数据分开；并表收入、归母利润、少数股东、股本、现金和EV／权益价值保持口径一致。

### 研究与实现

1. 从亏损路径出发，检验康波长期结构、朱格拉资本开支、库存和技术周期的支持与反证，不按固定年数自动判断当前阶段。
2. 验证终端需求→客户资本开支→订单→交付验收→盈利→回款。设备订单不直接等于收入；新品认证不等于规模利润。
3. 复算单季与TTM，解释低基数、季节性、一次性项目和现金占用。现价、未来终点与折现到今日的价值分开。
4. 三情景采用相同终点；假设明确，检验倍数不扩张或压缩；不编造共识、概率、确定收益或账户仓位。
5. 研究更新保存新日期版本，列明原假设、新事实、支持／削弱／证伪、估值影响及下一次复核。必要时比较前后模型，不覆盖事前判断。
6. 开发工具时先写能复现实际失误的测试，再修改实现；不要给每次普通文案变更增加测试。

### 验证与交付

| 变更 | 最小验证 | 何时扩大 |
| --- | --- | --- |
| 单一公司数据／模型 | `python3 scripts/research.py check <模型路径> --strict`，人工检查报告与模型一致 | 共享格式、公式或来源适配改变时运行全量 |
| 脚本、数据契约或初始化流程 | `make check` | 新的跨文件边界、失败或未解决问题出现时 |
| 文章源／索引工具 | `python3 scripts/article_library.py audit`，必要时检索原文 | 只在明确更新索引时运行 `index`，它会写索引文件 |
| 仓库技能／AGENTS | 运行 `$harness` 附带的结构校验、8＋8触发案例和一次演练 | 更改实际工作流时同时跑相关行为检查 |

交付前读实际diff；说明结论、文件、验证和未解决项。不自动commit、对外发布、发送消息或下单。

## 3. CLI与模型契约

运行环境为Python 3.9+，仅标准库。`check` 与 `list` 只读；`new` 只创建新文件。使用 `--root <临时目录>` 可演练，不污染真实案例。

```sh
python3 scripts/research.py new 002008-hans-laser --ticker 002008.SZ --as-of 2026-11-16 --name 大族激光
python3 scripts/research.py new 002008-hans-laser --ticker 002008.SZ --as-of 2026-11-15 --name 大族激光 --revision 2
python3 scripts/research.py check --strict --json
python3 scripts/research.py --root /tmp/baozhuo-dry-run list
```

`new` 创建待填数据和报告，绝不复制旧数字充当新事实。草稿允许存在，但 `--strict` 会失败；完成取证与人工复核后再将状态设为 `reviewed`。普通检查遇到结构、日期、来源或计算错误仍失败。

### 新模型格式

顶层字段：

| 字段 | 约束 |
| --- | --- |
| `schema_version` | 固定 `baozhuo-research/v1` |
| `as_of`、`status` | ISO日期；`draft`或人工复核后的`reviewed`；文件名日期与截止日相同 |
| `revision` | 正整数，默认1；第二版起文件名加`-r2`等后缀，与数据字段一致，旧版保留 |
| `ticker` | 六位代码加`.SH`／`.SZ`，与公司目录匹配 |
| `currency`、`raw_money_unit` | 固定`CNY`、`yuan`；原始财务金额统一为元 |
| `sources` | 来源ID→`date`、`url`；可加`retrieved_at`、`kind`、`local_path`与`sha256` |
| `market` | `date`、`price`、`shares_asof`、`shares`、`source_ids`；可存`market_cap`供复算 |
| `raw` | 期间→`source_ids`及四项财务原始值 |
| `derived` | 可选已存的TTM、单季或倍数结果；检查会复算，并在JSON输出显示核心结果 |
| `scenarios` | 至少悲观、基准、乐观三个假设，相同未来终点 |
| `limitations` | 关键未知与模型适用限制 |

所有金融数字写成十进制字符串，不用浮点数。`NaN`、`Infinity`、未知值假零及重复JSON键不能通过。比率为小数，如11%写`"0.11"`；原始股数为正整数。亏损TTM的PE应为`null`，不能将负PE当便宜；情景PE法仅支持未来正盈利情景，其他方法另行建模。

`raw`示例：

```json
{
  "2026M9": {
    "source_ids": ["q3_2026"],
    "revenue": "21474290338.33",
    "net_parent": "2177364859.14",
    "deduct_net_parent": "2301276096.57",
    "cfo": "226591913.04"
  }
}
```

这只是格式示例，不是新研究的默认值。支持12月年结A股的`YYYYFY`、`YYYYH1`、`YYYYM9`和`YYYYQ1`至`Q4`。每个期间必须有`revenue`、`net_parent`、`deduct_net_parent`、`cfo`。缺少来源或期间数据时维持草稿，不随意外推。

单季：Q1＝H1－Q2，Q2＝H1－Q1，Q3＝M9－H1，Q4＝FY－M9。TTM＝上一全年＋本期累计－上年同期；若只有完整全年，则采用该全年，不能冒充更近的滚动终点。JSON检查结果输出真实TTM截止日。

`sources`每项至少为`{"date":"2026-10-23","url":"https://…"}`。发布日期不能晚于研究截止日；用于财务期间的来源不能早于期间结束日。`local_path`如填写，必须位于仓库内且SHA-256匹配。下载哈希但不保留快照时，仅校验哈希格式，不能证明网页或文件内容。

`scenarios`每项包含：`name`（`bear`／`base`／`bull`）、`horizon`、`classification`（标明研究假设）、`revenue_cny_yi`（亿元）、`normalized_parent_net_margin`、`normalized_parent_net_profit_cny_yi`、`pe`、`terminal_price_cny_not_discounted`、`price_change_ex_dividend_fee_tax`。情景利润＝收入×正常化归母净利率；价格＝利润×1亿元÷股数×PE；价格变化＝情景价÷现价－1。未来价格不是今日内在价值。

### 历史兼容与检查边界

思瑞浦与大族激光2026-11-15模型保留原格式。适配器只读归一化字段名；大族激光原有复合来源ID明确映射到年报与三季报，其他未知来源仍报错。不要为了适配新工具改写旧投资判断。

自动检查覆盖：JSON／单位与数字、版本与证券代码、来源关联与前视日期、成对报告及本地链接、股价乘股数、单季与TTM核心财务值、所存核心倍数、三情景、部分反向估值及大族母子公司持股参考值。绝对金额允许分位误差，倍数和收益率采用更严格的小数误差。

自动检查**不覆盖**：网页真实性、PDF所有字段、报告文字中的每个数字、产业判断、假设合理性、来源质量、其余全部派生指标、DCF及完整分部估值。必须人工逐项复核本次使用的关键指标；`reviewed`是作者的复核声明，不是脚本认证或外部批准。

## 4. 中间资料与失败处理

中型任务按需使用 `_workspace/00_input`、`01_explore`、`02_plan`、`03_outputs`、`04_validation`，每次运行增加唯一子目录；旧结果需要移位时先归档，不能静默覆盖。该目录被Git忽略，正式依据和研究版本须另存至`references/`，不能只留工作区。

网络失败优先重试正式工具或改用可核验公开源；无法取得时明确缺口，保留草稿，不补造数字。权限被拒绝时停止对应写入，保留具体待安装成果，说明动作与原因；不绕过沙箱。测试失败先定位本次引入的问题，历史结论疑点另建有日期勘误，不无关重构。

默认Tier 0脚本＋Tier 1单父线程，不创建固定模型配置或额外角色。只有明确要求委派时才划分独立证据核验或文件范围；父线程拥有共享数据契约、结果整合和最终验证。发现冲突由父线程解决，超时只整合已完成部分并报告缺口。

同一失误重复两次，或一次出现高风险数据错误时，优先新增最小机械校验和回归样例，再考虑扩充自然语言规则。
